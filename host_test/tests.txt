init()

✅ Mutex creation success (já tem)
✅ Mutex creation fail (já tem)
✅ Semaphore creation fail (já tem)
❌ Init quando já inicializado retorna true e não recria recursos (idempotência)
❌ Status é IDLE após init bem-sucedido (já tem implícito, mas vale ser explícito)

deinit()

❌ Deinit sem task criada limpa recursos sem erros
❌ Deinit com task ativa notifica STOP_BIT e aguarda shutdown_done
❌ Deinit com timeout no shutdown_done loga warning mas continua
❌ Deinit deleta mutex e semaphore
❌ Deinit chama abort() no ota_session
❌ Deinit seta status para IDLE
❌ Múltiplos deinit() são seguros (idempotência)

start_ota()

❌ Start quando status != IDLE/FAILED retorna false
❌ Start quando status == IDLE cria task e notifica START_BIT
❌ Start quando status == FAILED cria task e notifica START_BIT
❌ Start quando task já existe apenas notifica START_BIT (não recria)
❌ Start quando create_task falha retorna false

cancel_ota()

❌ Cancel chama abort() no ota_session
❌ Cancel notifica CANCEL_BIT se task está ativa
❌ Cancel sem task ativa apenas chama abort()

Categoria 3: Thread Safety (get_status)
get_status()

❌ Retorna status sem travar se mutex == nullptr
❌ Retorna status sem travar se semaphore_take falha
❌ Retorna status protegido por mutex quando disponível


Testes dos Handlers (Lógica de Estado) — SUGESTÃO: tornar protected
Se você tornar os métodos handle_*_state() protegidos, pode testar a lógica de cada estado isoladamente, sem depender da task real. Isso é altamente recomendado para máxima cobertura.
handle_manifest_state()

❌ Fetch falha → retorna FAILED
❌ Parse falha → retorna FAILED
❌ Parse sucesso → popula manifest_ e retorna SUCCESS

handle_version_state()

❌ Device type mismatch → retorna FAILED
❌ Falha ao parsear versão atual → retorna FAILED
❌ Versão do manifest é menor → retorna FAILED
❌ Versão igual com allow_same_version=false → retorna FAILED
❌ Versão igual com allow_same_version=true → retorna SUCCESS
❌ Versão do manifest é maior → retorna SUCCESS

handle_download_state()

❌ Session não ativa: begin() falha → retorna FAILED
❌ Session não ativa: get_img_desc() falha → abort + FAILED
❌ Session não ativa: versão da imagem inválida → abort + FAILED
❌ Session ativa: perform() retorna IN_PROGRESS → retorna IN_PROGRESS
❌ Session ativa: perform() falha → abort + FAILED
❌ Session ativa: is_complete() false → abort + FAILED
❌ Session ativa: finish() falha → retorna FAILED
❌ Download completo: retorna SUCCESS

handle_verification_state()

❌ get_update_partition() retorna nullptr → FAILED
❌ get_partition_sha256() falha → FAILED
❌ SHA256 não bate com manifest → FAILED
❌ SHA256 bate → retorna SUCCESS

Categoria 4: Estados e Transições
1. Fluxo Completo de Sucesso (Happy Path)
  Este teste garante que, ao iniciar uma atualização, o OtaManager passa por todos os estados corretamente até
  solicitar o restart.
   - Passos:
       1. Mockar http_client.fetch para retornar um JSON de manifesto válido.
       2. Mockar manifest_parser.parse para retornar um objeto OtaManifest.
       3. Mockar system.get_running_app_desc para retornar uma versão inferior à do manifesto.
       4. Mockar ota_session (begin, write, end) para retornarem ESP_OK.
       5. Chamar ota_manager.start_ota().
       6. Verificação: Validar se o status passa por MANIFEST_FETCH, DOWNLOADING, VERIFYING e finalmente
          atinge READY_TO_RESTART, disparando system.restart().

  2. Cancelamento da OTA
  Verifica se a task interrompe o processo imediatamente quando solicitado.
   - Passos:
       1. Mockar o processo até o estado de DOWNLOADING.
       2. Configurar o mock de download para "travar" ou demorar (usando uma ação customizada no GMock).
       3. Chamar start_ota().
       4. Chamar ota_manager.cancel_ota().
       5. Verificação: Validar se a task chama ota_session.abort() e se o status volta para IDLE.

  3. Falha no Download / Rede
  Verifica a resiliência a falhas de comunicação.
   - Passos:
       1. Mockar o manifesto com sucesso.
       2. Mockar ota_session.begin ou write para retornar ESP_FAIL.
       3. Chamar start_ota().
       4. Verificação: Validar se o status muda para FAILED e se os recursos da sessão são liberados.

  4. Validação de Versão (Downgrade ou Mesma Versão)
  Garante que o sistema não tente atualizar para uma versão mais antiga, a menos que permitido.
   - Passos:
       1. Mockar manifesto com uma versão menor ou igual à atual.
       2. Configurar allow_same_version = false.
       3. Chamar start_ota().
       4. Verificação: Validar se o status vai para FAILED logo após o VERSION_CHECK.

  5. Shutdown da Task (Deinit)
  Verifica se a task encerra corretamente quando o componente é desinicializado.
   - Passos:
       1. Chamar init() e start_ota().
       2. Chamar deinit().
       3. Verificação: Validar se a task deixa de existir e limpa os semáforos/mutexes.
